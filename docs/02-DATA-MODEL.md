# 02 — Data Model (D1 + Durable Object SQLite + R2)

Conventions: ids are UUIDv7 `TEXT` (time-sortable — matters, SQLite has no `gen_random_uuid()`), timestamps are `INTEGER` epoch-ms UTC, migrations are forward-only in `migrations/NNNN_name.sql` generated by `drizzle-kit`. SQLite enforces `FOREIGN KEY`s only when `PRAGMA foreign_keys=ON` — **D1 enables this by default; do not disable it.**

> **There is no RLS here.** Every access rule in §5 is enforced by `src/server/policy/` and tested per 07 §2. A missing check is a data breach with no second line of defense.

## 1. D1 schema

```sql
-- migrations/0001_init.sql

-- ── Better Auth owns these four; generate with `npx @better-auth/cli generate`.
-- Listed for reference; do not hand-edit.
CREATE TABLE user (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, email TEXT NOT NULL UNIQUE,
  emailVerified INTEGER NOT NULL DEFAULT 0, image TEXT,
  createdAt INTEGER NOT NULL, updatedAt INTEGER NOT NULL
);
CREATE TABLE session (
  id TEXT PRIMARY KEY, userId TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  token TEXT NOT NULL UNIQUE, expiresAt INTEGER NOT NULL,
  ipAddress TEXT, userAgent TEXT, createdAt INTEGER NOT NULL, updatedAt INTEGER NOT NULL
);
CREATE TABLE account (/* password hash lives here */);
CREATE TABLE verification (/* email verify + reset tokens */);
CREATE INDEX idx_session_user ON session(userId);

-- ── app profile (1:1 with user; keeps our columns out of Better Auth's table)
CREATE TABLE profiles (
  user_id      TEXT PRIMARY KEY REFERENCES user(id) ON DELETE CASCADE,
  display_name TEXT NOT NULL,
  avatar_key   TEXT,                       -- R2 object key
  status_text  TEXT,
  last_seen_at INTEGER NOT NULL DEFAULT 0,
  storage_used INTEGER NOT NULL DEFAULT 0, -- bytes, maintained on attachment ready/delete
  created_at   INTEGER NOT NULL,
  CHECK (length(display_name) BETWEEN 1 AND 50),
  CHECK (status_text IS NULL OR length(status_text) <= 140)
);

-- ── friendships: ONE row per pair, canonical order (user_a < user_b lexically)
CREATE TABLE friendships (
  id           TEXT PRIMARY KEY,
  user_a       TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  user_b       TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  requested_by TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  blocked_by   TEXT REFERENCES user(id) ON DELETE SET NULL,
  status       TEXT NOT NULL DEFAULT 'pending'
               CHECK (status IN ('pending','accepted','declined','blocked')),
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  CHECK (user_a < user_b),
  CHECK (user_a <> user_b),
  UNIQUE (user_a, user_b)
);
CREATE INDEX idx_fr_a ON friendships(user_a, status);
CREATE INDEX idx_fr_b ON friendships(user_b, status);

-- ── invitations to non-users
CREATE TABLE invitations (
  id         TEXT PRIMARY KEY,
  inviter_id TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  email      TEXT NOT NULL,                -- stored lowercased+trimmed
  token_hash TEXT NOT NULL UNIQUE,         -- sha256(raw); raw never stored or logged
  claimed_by TEXT REFERENCES user(id) ON DELETE SET NULL,
  claimed_at INTEGER,
  expires_at INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_inv_inviter ON invitations(inviter_id, created_at DESC);
CREATE INDEX idx_inv_email ON invitations(email);

-- ── conversations (v1: exactly one per accepted friendship)
CREATE TABLE conversations (
  id             TEXT PRIMARY KEY,
  friendship_id  TEXT NOT NULL UNIQUE REFERENCES friendships(id) ON DELETE CASCADE,
  -- denormalized from ConversationDO (see 01 §3 "the one crossing")
  last_message_at      INTEGER,
  last_message_preview TEXT,
  last_message_sender  TEXT,
  last_seq             INTEGER NOT NULL DEFAULT 0,
  created_at     INTEGER NOT NULL
);

CREATE TABLE conversation_members (
  conversation_id TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  user_id         TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  last_read_seq   INTEGER NOT NULL DEFAULT 0,
  muted_until     INTEGER,
  PRIMARY KEY (conversation_id, user_id)
);
CREATE INDEX idx_cm_user ON conversation_members(user_id);

-- ── attachments (metadata in D1, bytes in R2)
CREATE TABLE attachments (
  id              TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  uploader_id     TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  r2_key          TEXT NOT NULL UNIQUE,     -- att/{conversation_id}/{id}.{ext}
  mime_type       TEXT NOT NULL,            -- server-sniffed, not client-declared
  byte_size       INTEGER NOT NULL,
  original_name   TEXT,
  width INTEGER, height INTEGER,
  duration_ms INTEGER,
  waveform        TEXT,                     -- JSON array of 64 ints, voice only
  status          TEXT NOT NULL DEFAULT 'pending'
                  CHECK (status IN ('pending','ready','failed','deleted')),
  created_at      INTEGER NOT NULL,
  CHECK (byte_size > 0 AND byte_size <= 26214400)   -- 25 MiB
);
CREATE INDEX idx_att_conv ON attachments(conversation_id);
CREATE INDEX idx_att_pending ON attachments(status, created_at);

-- ── calls (history; live state lives in CallDO)
CREATE TABLE calls (
  id              TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
  caller_id       TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  callee_id       TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  status          TEXT NOT NULL DEFAULT 'ringing'
                  CHECK (status IN ('ringing','active','ended','missed','declined','failed')),
  started_at INTEGER, ended_at INTEGER,
  end_reason TEXT, ice_relayed INTEGER,
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_calls_conv ON calls(conversation_id, created_at DESC);
CREATE INDEX idx_calls_active ON calls(callee_id, status);

-- ── push subscriptions
CREATE TABLE push_subscriptions (
  id         TEXT PRIMARY KEY,
  user_id    TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  endpoint   TEXT NOT NULL UNIQUE,
  p256dh     TEXT NOT NULL,
  auth       TEXT NOT NULL,
  user_agent TEXT,
  created_at INTEGER NOT NULL,
  last_ok_at INTEGER
);
CREATE INDEX idx_push_user ON push_subscriptions(user_id);

-- ── abuse
CREATE TABLE reports (
  id TEXT PRIMARY KEY,
  reporter_id TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  target_id   TEXT NOT NULL REFERENCES user(id) ON DELETE CASCADE,
  conversation_id TEXT, message_seq INTEGER,
  reason TEXT NOT NULL, created_at INTEGER NOT NULL
);
```
Rate limits are **not** a D1 table — they live in `RateLimiterDO` (atomic, no write amplification on a database billed per row written).

## 2. ConversationDO SQLite schema

Created in the constructor under `blockConcurrencyWhile` (schema only).

```sql
CREATE TABLE IF NOT EXISTS messages (
  seq        INTEGER PRIMARY KEY AUTOINCREMENT,   -- gapless, single writer
  id         TEXT NOT NULL UNIQUE,                -- UUIDv7, stable across clients
  client_id  TEXT NOT NULL UNIQUE,                -- idempotency key from sender
  sender_id  TEXT NOT NULL,
  kind       TEXT NOT NULL DEFAULT 'text',        -- text|file|image|voice|call_event|system
  body       TEXT,
  attachment_id TEXT,
  call_id    TEXT,
  reply_to_seq INTEGER,
  deleted_at INTEGER,
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_msg_created ON messages(created_at DESC);

CREATE TABLE IF NOT EXISTS receipts (
  user_id      TEXT NOT NULL,
  delivered_seq INTEGER NOT NULL DEFAULT 0,
  read_seq      INTEGER NOT NULL DEFAULT 0,
  updated_at    INTEGER NOT NULL,
  PRIMARY KEY (user_id)
);

CREATE TABLE IF NOT EXISTS members_cache (
  user_id  TEXT PRIMARY KEY,
  status   TEXT NOT NULL,          -- 'active' | 'blocked'
  synced_at INTEGER NOT NULL
);
```
Notes:
- **Receipts are per-user high-water marks, not per-message rows.** One row per member instead of one per message per member — ~1000× fewer writes for the same UI.
- `UNIQUE(client_id)` is the whole offline-retry story: `INSERT ... ON CONFLICT(client_id) DO NOTHING RETURNING *`, then `SELECT` the existing row. Never a duplicate, no matter how many times the outbox retries.
- Message body cap 4000 chars enforced in the zod schema *and* re-checked in the DO.
- Retention alarm: prune `deleted_at < now-30d`; hard cap 50 000 rows per conversation, oldest archived to R2 as NDJSON (v2; v1 just warns in metrics).

## 3. CallDO / UserDO / RateLimiterDO state

`CallDO` (KV storage, tiny):
```ts
type CallState = {
  callId: string; conversationId: string; callerId: string; calleeId: string;
  status: 'ringing'|'connecting'|'active'|'ended';
  createdAt: number; startedAt?: number; endedAt?: number; endReason?: string;
  relayed?: boolean;
};
```
`UserDO`: `{ presence: 'online'|'away'|'offline', lastSeenAt, unread: Record<conversationId, number> }`.
`RateLimiterDO` SQLite: `counters(action TEXT, window_start INTEGER, count INTEGER, PRIMARY KEY(action, window_start))`.

## 4. R2 layout

| Bucket | Key pattern | Access |
|---|---|---|
| `ripple-media` | `att/{conversationId}/{attachmentId}.{ext}` | presigned PUT (15 min) after policy check; presigned GET (1 h) |
| | `avatar/{userId}/{uuid}.webp` | presigned PUT by owner; presigned GET for friends |
| | `export/{userId}/{jobId}.zip` | presigned GET (24 h), lifecycle-deleted at 7 days |

Lifecycle rules: abort incomplete multipart after 1 day; delete `export/` after 7 days. Bucket is private — no public `r2.dev` domain, no custom domain binding.

## 5. Authorization matrix (this replaces the RLS policy list)

Each row is a function in `src/server/policy/` with an allow-test and a deny-test.

| Action | Rule |
|---|---|
| read profile | self, or `assertFriends(actor, target)` (accepted, not blocked). Otherwise 404 — never 403, which confirms existence |
| update profile | self only; `display_name`/`status_text`/`avatar_key` only |
| create friendship | `requested_by === actor`, target ≠ actor, no existing accepted/blocked row, rate limit passes |
| accept / decline | actor is a member **and** `requested_by !== actor` |
| block | either member; sets `status='blocked'`, `blocked_by=actor` |
| unblock | `blocked_by === actor` only |
| read conversation | row exists in `conversation_members` for actor |
| send message | member **and** friendship status is `accepted` (blocked ⇒ 403) **and** message rate limit passes |
| edit/delete message | `sender_id === actor` (delete = tombstone, body cleared) |
| set read marker | own `conversation_members` row only; `last_read_seq` may only increase |
| sign attachment upload | member + `byte_size` ≤ 25 MiB + `profiles.storage_used + size` ≤ 2 GiB |
| get attachment URL | member of the attachment's conversation + `status='ready'` |
| start call | member + friendship accepted + no other `ringing`/`active` call for actor + call rate limit |
| accept/decline/end call | `actor ∈ {caller_id, callee_id}`; only CallDO writes the final row |
| read call history | `actor ∈ {caller_id, callee_id}` |
| register push sub | self only; endpoint uniqueness handled by upsert |
| invite by email | verified email + 10/day |

**Enumeration rule:** any "not visible to you" case returns `404`, never `403`, except for the explicitly blocked case inside a conversation the actor is a member of.

## 6. KV usage
| Key | Value | TTL |
|---|---|---|
| `sess:{token}` | `{userId, expiresAt}` (Better Auth secondary storage) | session TTL |
| `ice:{userId}` | minted ICE config | 3300 s |
| `rl:soft:{ip}:{route}` | coarse per-IP counter for unauthenticated routes | 60 s |
KV is eventually consistent — **never** use it for authorization decisions that must be immediate (e.g. a block taking effect). Session revocation deletes both the KV key and the D1 row, and the D1 row is authoritative on miss.

## 7. Client-side (IndexedDB via Dexie)
```ts
db.version(1).stores({
  conversations: 'id, lastMessageAt',
  messages:      '[conversationId+seq], conversationId, clientId, createdAt',
  outbox:        'clientId, status, createdAt',
  blobs:         'attachmentId',
  meta:          'key',        // lastSeq per conversation, device id, prefs
});
```
`lastSeq` per conversation drives the gap-fill handshake in 01 §4.1. Prune: messages older than 90 days or beyond 2 000 rows/conversation; blobs LRU over 300 MB.

## 8. Migration workflow
```bash
# edit src/server/schema.ts (drizzle), then
pnpm drizzle-kit generate            # writes migrations/NNNN_*.sql
pnpm wrangler d1 migrations apply ripple --local
pnpm wrangler d1 migrations apply ripple --remote   # prod, via CI only
```
Rules: never edit an applied migration; SQLite cannot drop or retype a column in place — generate the `CREATE new / INSERT SELECT / DROP / RENAME` sequence and include a rollback migration in the same PR. **DO SQLite schemas migrate themselves** in the DO constructor with `CREATE TABLE IF NOT EXISTS` plus a `user_version` pragma check — versioned, forward-only, and run per object on first touch.
